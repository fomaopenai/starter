Следим за тем чтобы были разделены следующие слои приложения\
\
- конфиги приложения (работаем с env) \
- зависимости\
- миграции\
- модели\
- слой работы с данными (запросы в апи, с3, бд, кафку и т д)\
- бизнес логика\
- web интерфейс\
- единая точка входа где описаны все команды для приложения

Для соблюдения такого подхода в сервисах организована структура вида:

- **app** - Директория с логикой приложения. Описанием всех usecase-ов, моделей, и тд. Содержит следующие директории:
  - **models** - модели сущностей с которыми работает приложение (alembic, marshmallow, etc)
  - **repositories** - уровень данных. отвечает за логику создания, доступа, редактирования. Не содержит бизнес логики.
  - **services** - уровень бизнес логики. Этот уровень не знает про web и не знает про низкоуровневые детали хранения сущностей (БД, s3, файловая система, другие сервисы и пр.)
- **web** - Директория с логикой работы web приложения. Описание endpoint'ов, построение apispec, и пр.
  - [**routes.py**](http://routes.py)** **- определяет перечень всех endpoint'ов
  - **api** - директория, содержит описание endpoint'ов: схемы входных/выходных параметров, apispec, код вызова определенного сервиса из app/services.
- **settings** - Настройки приложения, константы и переменные окружения.
- **helpers / utils** - Общие инструменты не содержащие бизнес-логики
- **requirements** - Директория с описанием зависимостей приложения
- **docker-compose.yml** - поднимает все зависимости приложения (БД, s3, очереди), для **локальной** разработки
- [**manage.py**](http://manage.py) - единая точка входа где описаны все консольные команды для приложения

### Конфигурация

Проект конфигурируется с помощью **pyproject.toml** файла (вместо setup.cfg и requirements.txt), который содержит dev и prod зависимости, конфиги линтеров и pytest'а. Пример pyproject.toml:

| ``` [project] name = "fingular-docs" requires-python = ">=3.10" version = "0.1.0"  dependencies = [     # основные зависимости проекта ]  [dependency-groups] dev = [     # зависимости для локальной разработки: тесты, линтеры     # в качестве линтеров Makfile использует ruff и mypy,     # поэтому лучше их себе добавить ]  [tool.pytest.ini_options] asyncio_mode = "auto" addopts = "-ra --strict-config" markers = [     "slow: marks tests as slow (deselect with '-m \"not slow\"')",     "prepare_db: prepare db before tests and clean it after", ] filterwarnings = [     "ignore::DeprecationWarning", ] testpaths = [     "tests", ]  [tool.coverage.run] omit = [     "settings/*",     "manage.py", ]  [tool.ruff] target-version = "py310" line-length = 120  [tool.ruff.lint] select = [     "E4", # pycodestyle errors     "E7",     "E9",     "F", # pyflake     "B", # flake8-bugbear     "COM812", # trailing comma     "W292", # no newline at EoF ] ignore = [     "F403", # unable to detect undefined names ] exclude = [     ".git",     ".venv",     "venv",     ".mypy_cache",     ".pytest_cache",     ".ruff_cache",     "logs",     "tmp",     "alembic",     "*.egg-info",     "build",     "dist",     "__pycache__", ]  [tool.ruff.lint.per-file-ignores] "__init__.py" = ["F401"] # These modules can contain unused imports "tests/*" = ["F401"] "settings/*.py" = ["F401"] "*example*.py" = ["F841"] # Local variable can be assigned but never used in examples code  [tool.ruff.format] quote-style = "single"  [tool.mypy] check_untyped_defs = true disallow_untyped_decorators = true disallow_any_explicit = true ignore_errors = false ignore_missing_imports = true local_partial_types = true strict_optional = true strict_equality = true warn_no_return = true  [tool.darglint] docstring_style= "sphinx"  ``` |

### Зависимости

В качестве пакетного менеджера используем `uv` ([ссылка на документацию в confluence](https://confluence.fingular.com/spaces/PB/pages/142644478/%D0%9F%D0%B0%D0%BA%D0%B5%D1%82%D0%BD%D1%8B%D0%B5+%D0%BC%D0%B5%D0%BD%D0%B5%D0%B4%D0%B6%D0%B5%D1%80%D1%8B#id-%D0%9F%D0%B0%D0%BA%D0%B5%D1%82%D0%BD%D1%8B%D0%B5%D0%BC%D0%B5%D0%BD%D0%B5%D0%B4%D0%B6%D0%B5%D1%80%D1%8B-Uv)). Версии всех зависимостей фиксируем в `uv.lock`  файле в корне проекта. `uv.lock`  генерируется `uv` автоматически

### Docker

Пример типового **Dockerfile** (python3.10):

| ``` FROM registry.mychili.id/docker.io/python:3.10-slim as base ARG PYPI_TOKEN  # install build dependencies (if needed) RUN apt-get update && apt-get install -y build-essential && apt-get clean && rm -rf /var/lib/apt/lists/*  # install uv COPY --from=ghcr.io/astral-sh/uv:0.8.3 /uv /uvx /bin/  # use the system interpreter to install packages globally ENV UV_PROJECT_ENVIRONMENT=/usr/local # pre-compile bytecode ENV UV_COMPILE_BYTECODE=1  WORKDIR /app  COPY pyproject.toml uv.lock ./  # install dependecies RUN uv sync --locked --no-dev --extra-index-url https://__token__:${PYPI_TOKEN}@gitlab.mychili.id/api/v4/projects/25/packages/pypi/simple && unset PYPI_TOKEN  # use final image without uv FROM registry.mychili.id/docker.io/python:3.10-slim  # install only runtime dependencies (if needed) RUN apt-get update && apt-get install -y postgresql-client graphviz default-jre && apt-get clean && rm -rf /var/lib/apt/lists/*  # copy installed deps from base build COPY --from=base /usr/local /usr/local  WORKDIR /app  # copy app COPY ./ /app/  ``` |

Чтобы тесты не оказывались в билде, добавляем **.dockerignore** файл, который возволяет исключить файлы из контекста билда. В .dockerignore файле должна быть дикертория `tests/`

#### Доступные команды

| Команда                                         | Описание                                                        |
| :---------------------------------------------- | :-------------------------------------------------------------- |
| make help                                       | показать краткую справку                                        |
| make install-uv                                 | глобальная установка `uv`                                       |
| make install                                    | установить все зависимости проекта                              |
| make install-dev                                | установить все зависимости для локальной работы                 |
| make run                                        | запуск приложения                                               |
| make lint                                       | проверка линтерами диффа текущей ветки с мастером (ruff + mypy) |
| make test                                       | запуск всех тестов                                              |
| make format                                     | форматирование ruff'ом диффа текущей ветки с мастером           |
| make format-all                                 | форматирование ruff'ом всего проекта                            |
| make db-migrate 'migration name or description' | создание новой миграции                                         |
| make db-upgrade                                 | применить все миграции                                          |
| make db-downgrade                               | откатить последнюю миграцию                                     |
| make db-history                                 | история миграций                                                |
| make db-reset                                   | откатить схему БД и применить все миграции заново               |
| make docker-run                                 | запуск проекта через docker-compose                             |
| make docker-stop                                | остановка всех docker-compose сервисов                          |
| make docker-logs                                | логи docker-compose сервисов                                    |
| make docker-rebuild                             | перебилд docker-compose сервисов                                |
| make docker-infra                               | запуск инфраструктурных сервисов                                |
| make clean                                      | удалить кэши линтеров и тестов                                  |
| make kill-server                                | убить python-процессы, запущенные сервисом                      |
| make kill-server-force                          | force-kill python-процессы, запущенные сервисом                 |
| make server-status                              | проверка статуса сервиса                                        |
